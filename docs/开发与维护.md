# 开发与维护

## 配置

`pnpm setup:env` 从 `.env.example` 创建 `.env.local`，为应用密钥和初始密码生成独立随机值，文件权限为 0600。已有文件不会覆盖。环境文件只留在运行环境，不提交到 Git。

- `DATABASE_URL`：PostgreSQL 连接。开发示例只适合本机。
- `PAYLOAD_SECRET`：至少 32 字符的随机密钥，不能使用示例或默认值。应用认证与规划导入签名共用它。
- `SEED_EMAIL`、`SEED_PASSWORD`：仅首次创建管理员使用。已有管理员不会被 seed 重设。
- `SERVER_URL`：实际 HTTPS 地址，用于 CSRF 与安全 Cookie 配置。
- `UPLOAD_DIR`：持久化媒体目录。
- `GEO_BUILD_WORKERS`：可选，限制构建并发。

有效密钥应在升级时保留；主动更换会使已有认证和导入预览凭证失效。不要把密钥放在 `NEXT_PUBLIC_` 环境变量里。

## 数据初始化与升级

新建空库首次初始化可执行 `PAYLOAD_DB_PUSH=true pnpm db:seed`，随后运行 `pnpm db:migrate` 和 `pnpm db:check`。自动 push 仅用于首次空库建表，不能作为业务库升级手段。

已有数据库更新前备份数据库与媒体，然后运行显式增量迁移和检查。迁移会把受影响表备份到 `.backups/`，该目录含业务数据，只应保存在受保护的运行环境。源码和业务数据需要分别回滚。

## 验证

类型、业务纯逻辑、正文表格、初始化安全与 Agent 客户端使用 README 中的命令验证。修改数据关系、导入、审核或发布逻辑后，运行 `pnpm test:isolated`。

完整回归使用临时数据库和源码副本，构建后在默认 3002 端口运行，结束删除临时数据库和源码。可用 `TEST_PORT` 调整端口。该流程需要本地数据库账号具有创建数据库权限。

## 公开内容检查

提交前运行 `pnpm check:public`，检查 Git 跟踪和未忽略文件。检查包含私钥、常见平台 token、非示例凭据和不应提交的数据文件；这不是对所有秘密格式的完整识别，仍需要审查实际变更。

不要提交环境文件、会话 Cookie、数据库导出、客户内容、媒体原件或内部部署记录。提交示例数据时使用虚构名称。问题报告只提供脱敏复现步骤。
